# 新しい予想モデル（ml-chain）

今のモデル（`prediction.predict`）は、基礎データだけで学習した1着確率に、今節・コース・気象などの
補正を人が決めた重みで後から足している。新しいモデルは、情報をまとめて特徴量にし、
1着・2着・3着の確率を最初から学習する。後から足す補正は無い。

検証の結果（成績の数字）は公式データから計算したものなので、非公開のデータ用リポジトリの
`reports/ml_v1/REPORT.md` にだけ置いている。

**本番の予想はまだ今のモデルのまま。** 切り替えるまで新しいモデルはどこからも呼ばれない。

## 仕組み

| 段 | 学習するもの | 学習の単位 |
|---|---|---|
| 1着 | P(艇i が1着) | 1レースの6艇の中の割合（多項ロジット） |
| 2着 | P(艇j が2着 \| 1着が艇a) | 1着艇を除いた5艇の中の割合。1着艇の艇番・強さと、候補艇との位置関係も特徴量にする |
| 3着 | P(艇k が3着 \| 1着a・2着b) | 残り4艇の中の割合。1着艇・2着艇の両方を特徴量にする |

- 3連単 a-b-c ＝ 1着(a) × 2着(b\|a) × 3着(c\|a,b)。120通りの合計は1。
- 学習は LightGBM。各段の目的関数は「レースの中の割合（softmax）の対数尤度」（`ml_model._softmax_objective`）。
- 確率の調整は、各段の温度1つだけ。学習に使っていない直近の期間で決める（人が重みを決める補正ではない）。
- 出力は `prediction.predict` と同じ形（`p_first`・`p_second`・`p_third`・`p_second_given_<a>`・
  `p_third_given_<a>_<b>`）。`prediction.trifecta` は新しいモデルの版を見たときだけ掛け算で3連単を出すので、
  買い目の作り方（`adaptive_ticket_plan`・`rank_tickets`）・資金配分・画面はそのまま使える。

## 特徴量（`ml_features.py`）

`FEATURE_GROUPS` に9分類で並べている: 選手の実力・選手×コース・選手×場・スタート・今節・機材・
気象/水面・レース条件・艇同士の関係。潮位・ピットレポート・オリジナル展示・オッズは使わない。

特徴量の表との照合で足した列（v2。`V2_ADDED`）: 前走の着順・登録番号（経験年数の代わり）・コース別のST順位・
コース別の決まり手（逃げ・まくり・差し・まくり差しで勝った割合）・当地の出走経験数（全期間）・今節の前走と流れ
（直近2走−それ以前。本番の `current_meet_fetcher` も同じ関数で計算）・締切時刻とナイター・残りの項目のレース内順位・
1号艇と2号艇のST差・外枠の強さの合計と最大。

「艇番を除いた実力での最強艇」は、艇番・コース・隣の艇の列を使わずに1着を学習した小さなモデル
（`LANE_FREE_FEATURES`）の確率から作る（`la_p`・順位・最強艇との差・最強艇の艇番）。学習データの行には、
その行を含まない期間で学習した値を付ける（自分の結果を見た値が混ざらないように）。

そのレースの時点で分かっていた情報だけを使う:

- 番組表（Bファイル）・出走表/直前情報・競走成績の展示タイムはレース前に出ている値
- 進入コース・ST・着順は結果なので、そのレース自身の値は使わず、それより前のレースの集計にだけ使う
  （選手の直近365日/90日・選手×コース・選手×場・直近180日のST・級別審査期間内のF回数・モーター）
- 今節成績は、同じ節のそのレースより前に終わったレースだけ。定義は本番の `current_meet_fetcher` と同じ
- 直前情報の無い期間の気象は、同じ場・同じ日の1つ前のレースの値
- 勝率・2連率・レース名は番組表の値（出走表ページの保存値は節の中で使い回しているため）

学習用（`build_table`）と本番用（`live_table`）は同じ `assemble` を通し、1日分の全レースで全項目が
一致することを確かめている。

## 版と戻し方

- 版の名前: `ml-chain-v2-lgb-2y-<学習日>`。学習済みファイルはデータ用リポジトリの `models/<版>.joblib`
  （設定・学習期間・温度は同じ名前の `.json`）。`models/latest.json` が最新の版を指す。
- 使うモデルは `ml_live.selected_model()` で決める（app_settings の `prediction_model`、無ければ環境変数
  `PREDICTION_MODEL`）。既定は `current`（今のモデル）。`ml` なら最新の版、版の名前を書けばその版に固定。
  `current` に戻せばいつでも今のモデルに戻る。今のモデルのコードは消していない。
- 事後予想（hindcast）では `model_version` に版の名前が入るので、新旧を同じ表で並べて比べられる。

## 本番への入れ方（確認後）

1. `ML Model` ワークフローを `task=train` で動かし、最初の版を `models/` に作る
2. `ML Model` を `task=state` で毎晩、`Hindcast` を `model=ml` で毎晩動かす（pg_cron に2つ足す）。
   新モデルの事後予想は、出走表・直前情報が History Backfill で集まった翌晩に作られる（1日遅れ）
3. 1週間ほど並べ、合格基準（データ用リポジトリの報告書 6章）を満たすか確かめる
4. 合格なら app_settings の `prediction_model` を `ml` にする（アプリ・自動固定が新モデルを使う配線はこの段階で入れる）

## 学習データの更新と学習し直し（提案）

| 処理 | 頻度 | 時間の目安 | 中身 |
|---|---|---|---|
| 過去データの収集 | 毎晩（今のまま） | — | History Backfill・Collect History |
| 前日までの集計表 | 毎晩（朝の開催前） | 数十秒 | `ml_nightly.py state` → `models/ml_state.pkl.gz`（約1.2MB） |
| 学習し直し | 週1回 | 数分 | `ml_nightly.py train`。直近28日で前の版より悪ければ latest を変えない |

アプリの動作を重くしないために:

- アプリでは学習しない（今のモデルは「AI最終予想」を押すたびに学習している）。学習済みファイル（約3MB）と
  集計表（約1.2MB）を1日1回ダウンロードして読み込むだけにする
- 1レースの予想は、出走表・直前情報の取得と、学習済みモデルでの計算だけ（手元で約0.5秒）
- 過去データ全体（data/history/）はアプリでは読まない
