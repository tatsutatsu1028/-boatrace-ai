# 3つの予想（モデルのみ／Claudeのみ／両方の予想平均）

管理者（owner）だけの機能。スタッフの画面は「🤖 モデルのみ予想」のボタンだけで、Claude の API は一切呼ばない
（「＋Claude予想」タブも出ない）。

## ボタン（予想タブ）

| ボタン | 中身 | Claude |
|---|---|---|
| 🤖 モデルのみ予想 | 今までどおりのモデルの買い目 | 呼ばない（前に取った Claude の予想があれば一緒に保存する） |
| 🧠 Claudeのみ予想 | Claude が選んだ3連単の買い目そのまま。資金配分はアプリの仕組み（allocate_stakes_smart） | 1回だけ呼ぶ |
| ⚖️ 両方の予想平均 | モデルと Claude の3連単の確率を組み合わせごとに平均し、モデルと同じ手順で買い目を選び直す | 1回だけ呼ぶ |

- 「Claudeのみ」か「両方の平均」を押すと Claude を1回だけ呼び、3つの予想をすべて計算して保存する。
  後から別のボタンを押しても、同じ入力なら呼び直さない（アプリの中のキャッシュと、保存済み予想の `"claude"` で判定）。
  展示データが出て入力が変わったときは、もう一度押すと新しく読む。
- 予想タブには押したボタンの買い目を出し（「表示中：…」）、その下に3つの予想の買い目を小さく並べる
  （モデルに無い買い目に★、各艇の1着確率（モデル・Claude・平均）と展開のまとめ）。
  Claude が取れなかったときは「取得できませんでした」と出し、モデルの買い目を表示する。
- 「この買い目の的中確率」の補正（事後予想の実績で作ったもの）はモデルの予想にだけ使い、Claude・平均は補正前の値を出す。

## Claude への依頼（`claude_reader.py`）

レースの入力データ（級別・勝率・当地勝率・モーター/ボート2連率・平均ST・F/L・体重・展示タイム・展示ST・チルト・
部品交換・今節成績・コース別成績・風・波・気温・水温）とモデルの1〜3着確率を渡し、次を受け取る:

- 各艇の1着確率と理由
- 3連単の買い目10点前後（本線・抑え）と、それぞれの組み合わせの確率・理由
- 1〜3着の展開のまとめ

データに無いことは書かない・1号艇を低く見すぎないことを指示している（`SYSTEM_PROMPT`）。
買い目は形・艇番・重なりを確かめ、おかしいものは除く。

### Claude が挙げなかった組み合わせの扱い（両方の予想平均）

Claude が挙げた10点前後の確率の合計を S とすると、残り（1 − S）を、挙げなかった組み合わせにモデルの確率の比率で配る
（`claude_full_tri`）。こうすると Claude の分も120通りで合計1になり、モデルと組み合わせごとに平均できる。
挙げなかった組み合わせを0にしないので、モデルが強く推す買い目が平均で消えすぎない。
平均した確率から、1着・条件付き2着・条件付き3着を作り直し（`final_from_tri`）、モデルと同じ手順（点数の決め方・
保険・補充・資金配分）で買い目を選ぶ。

## 保存と検証

- `prediction_snapshots.payload_json`: `"tickets"` にモデルの買い目（今までどおり）、`"claude"` に Claude の予想
  （1着確率・理由・まとめ・Claude が出した買い目）と、Claudeのみ予想の買い目（`claude_tickets`）、
  両方の予想平均の買い目（`avg_tickets`）を、金額付きで保存する。
- 結果確定後（自動の結果取り込み・オッズ追跡・手動保存）、`prediction_results` に3つの当たり外れが入る:
  - モデルのみ: `candidate_hit`・`hit_any_ticket`・`total_stake`・`payout`（今までどおり）
  - Claudeのみ: `claude_candidate_hit`・`claude_hit_any_ticket`・`claude_total_stake`・`claude_payout`
  - 両方の平均: `mix_candidate_hit`・`mix_hit_any_ticket`・`mix_total_stake`・`mix_payout`
  - 手動保存（着順と受取額を入力）では、Claude・平均の払戻は空になる（手入力の払戻は「100円あたり」ではないため）

## 予想と結果の照合（「＋Claude予想」タブの先頭「📋 今日の照合」）

その日に予想を保存したレースごとに、実際の3連単と、3つの予想それぞれの的中（○×）と払戻を並べる。
結果が無いレースは「結果待ち」、Claude の予想を取っていないレース（モデルのみ・自動固定）の Claude・平均は「－」。
最後に、その日の的中数・払戻・回収率の合計を3つ分出す。Supabase からはその日の行だけ、予想は6列・結果は11列だけを取り
（予想の中身 payload_json は取らない）、1分ごとに読み直す（`daily_review.py`）。

「＋Claude予想」タブには、ほかに各艇の1着確率と理由（モデル・Claude・平均）、3つの買い目（Claude は買い目ごとの理由つき）、
記事（note・スレッズ）に使う買い目の選択（既定は押したボタンの予想）、使ったモデルと費用を出す。

## 手動の結果保存

結果は自動で保存されるので、予想タブの手動の結果保存は外した（管理者・スタッフとも）。
自動で入らなかったときの予備は、検証タブの一番下「🔧 結果の手動保存」。

## 設定（Streamlit の Secrets）

| キー | 内容 | 既定 |
|---|---|---|
| `ANTHROPIC_API_KEY` | API キー | （必須） |
| `CLAUDE_READ_MODEL` | 予想に使うモデル | `claude-opus-5-5` |

Opus 系・Sonnet 5.5 では、安全上の理由で回答が控えられたときに別のモデルで自動でやり直す設定（server-side fallback）を付けている。

## 費用

- 1回あたり: 入力 約2,500トークン・出力 約2,000〜4,000トークン（考える分と買い目10点前後の理由を含む）で、
  Opus 5.5 だと 約0.05〜0.09ドル（8〜13円程度）。実際の値は「＋Claude予想」タブに毎回表示する。
- 1レースにつき1回（同じ入力なら、どのボタンを押しても呼び直さない）。
- 失敗・60秒を超える遅延のときは Claude の欄が「取得できませんでした」になるだけで、モデルの予想と買い目・保存は通常どおり。
