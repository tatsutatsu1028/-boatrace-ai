
# BOAT AI Mobile v2

スマホで使うことを前提にした Streamlit Webアプリ試作版です。

## 主な機能
- 日付 / 競艇場 / R を選択
- BOAT RACE公式ページから出走表系・直前情報をベストエフォート取得
- 展示タイム、展示ST、気象を反映
- 場別オリジナル展示（直線 / まわり足 / 1周）を入力可能
- 選手コメントを「伸び / 出足 / 回り足 / 乗り心地 / 総合気配」に解析
- 展示前 → 展示後の1着確率変化を表示
- 3連単120通りを計算
- 本線 / 抑え / 穴 に自動分類
- 3連単オッズ取得に成功した場合は期待値も表示
- CSV保存

## 学習データの置き場所
学習・過去データ（`sample_history.csv`・`history_full.csv`・`data/history/`）は公式データを
含むため、このリポジトリには置かず、非公開のデータ用リポジトリ
`tatsutatsu1028/-boatrace-ai-data` に置いています（`data_paths.py`）。

- Streamlitアプリ: Secrets の `DATA_REPO_TOKEN`（データ用リポジトリの Contents 読み取り専用トークン）で
  起動時に取得し、1時間ごとに更新を確認します
- GitHub Actions: Secrets の `DATA_REPO_TOKEN`（同 Contents 読み書き）で `_data/` に取り出し、
  収集したデータもデータ用リポジトリへコミットします
- 手元: データ用リポジトリのファイルをこのフォルダ直下に置くか、`BOATRACE_DATA_DIR` にその場所を指定します

## 全レースの事後予想（hindcast）
毎晩 01:40 JST（pg_cron → `hindcast.yml`）に、前日の全レースを今の本番の予想ロジックで予想し直し、
結果と突き合わせて Supabase に保存します（`hindcast.py`）。そのレースの時点で分かっていた情報だけを使います。

- `hindcast_predictions` … 1レース1行（1着確率・本命・買い目候補・実際の3連単・本命的中・候補内的中・モデルの版）
- `hindcast_inputs` … 1艇1行（予想に使った入力。結果の列は入れない）
- `hindcast_runs` … 1日1行（設定・学習データの範囲）

対象は 2026-08-18（1着モデルの学習データ `sample_history.csv` の翌日）以降の未保存の日です。

## 予想モデル
2026-10-15 から本番の予想は新しいモデル（1〜3着を特徴量からまとめて学習。`docs/ML_MODEL.md`）。
`app_settings.prediction_model` で切り替える（`ml` / `current` / 版の名前）。`current` に戻せば今までのモデルに戻る。

## 🌅 展示前厳選10（管理者だけ）
毎朝 08:05 JST（pg_cron → `pre_picks.yml`。朝の過去データ収集〜08:00 の後）に、その日の全レースを
展示・直前情報を使わない「展示前モデル」（`ml_pre.py`）で予想し、「この買い目の的中確率」が高い順に
10レースを選んで Supabase の `pre_exhibition_picks` に保存します（`pre_picks.py`）。公式サイトへは
番組表1つと各レースの出走表1ページずつ（開始間隔3.4秒以上）で、過去データの収集が動いていれば終わるまで待ちます。

- 表示: 予想タブの日付の下（管理者だけ）。会場・R・締切・的中確率・本命・買い目。「このレースを開く」でその下に読み込む
- 展示後: アプリか自動固定でそのレースを予想すると、トリガーが展示後の予想（今の新モデル）を同じ行に書き、
  買い目はそれに差し替わる。本命が変わった・的中確率が10ポイント以上下がったレースには印（外さない）
- 結果: 翌朝の同じ処理が、前の日までの的中・払戻を記録する（展示前の買い目と展示後の買い目の両方）。成績は同じ欄に出る
- 学習: 週1回の `ml_nightly.py train` が今の新モデルと一緒に学習し直し、`models/pre_latest.json` を書く
- 「当たりやすいレース」として表示する。検証（データ用リポジトリ `reports/pre_exhibition/`）で回収率は全レースと区別できない
- 止めるとき: `select cron.unschedule('trigger-pre-picks');`

## 💥 万舟チャンス（荒れやすいレース）
3連単の払戻が100円あたり1万円以上（万舟）になりやすいレースに印を付けます（`manshu.py`）。
レースごとの「万舟になる確率」は、新モデルの1着確率・3連単確率の散らばりと、級別・勝率の差・場・R などから
LightGBM で出します。検証（データ用リポジトリ `reports/manshu/REPORT.md`・`tools/manshu_eval.py`）では、
毎日上位10レースの万舟率が全体の約1.6倍で、展示前と展示後の差は小さい。回収率が上がる根拠は無いので、
「荒れやすいレース」として見せ、「儲かる」とは書きません。

- 選定: 毎朝の「🌅 展示前厳選10」と同じ処理（`pre_picks.py`）が、その日の全レースの展示前版の万舟確率を出し、
  高い順に10レースを Supabase の `manshu_chance_picks` に保存する（全レースの確率は `pre_exhibition_runs.manshu_prob_by_race`）。
  万舟チャンスだけ失敗しても厳選10は続ける（理由は `pre_exhibition_runs.manshu_error`）
- 展示後: アプリか自動固定で予想すると、展示後版の万舟確率と穴寄りの買い目を保存する予想
  （payload の `prediction_model.manshu_post`）に残し、印のレースはトリガーが `manshu_chance_picks.post_*` に写す
- 表示: 会場選択（💥と数）・Rカード（💥）・予想タブの日付の下の一覧・展示前厳選10（両方に入るレース）・
  予想画面（注意書き「本命が来にくい傾向」）。管理者には予想画面に参考の穴寄りの買い目
  （1号艇を1着から外した上位10点・資金配分しない）と、一覧の下に成績
- 結果: 翌朝の同じ処理が、万舟だったか・本線（展示前の買い目）と穴寄り（各100円として）の的中・払戻を記録する
  （展示後の買い目があればそれも）
- 学習済みファイル: データ用リポジトリの `models/manshu_latest.json`（版と、展示前版・展示後版のファイル名）。
  今は検証で作った版（学習 2025-08〜2026-07）を使う。学習し直しは `tools/manshu_eval.py eval` の結果を
  確かめてから `models/` に置き、`manshu_latest.json` を書き換える
- データベース: `supabase/migrations/20261018000000_create_manshu_chance_picks.sql`（SQL Editor で実行する。
  実行前は画面に「保存先の表がまだありません」と出て、印は付かない。厳選10は止まらない）
- 万舟チャンスだけ選び直す: `Pre-exhibition Picks` を task=manshu で動かす（厳選10は変えない。締切が近い・過ぎたレースは候補に入らない）

## 🧵 スレッズ・note の投稿（管理者だけ）
### 朝の無料3レース（スレッズの自動投稿）
毎朝 09:00 JST（pg_cron → `threads_morning.yml`）に、その日の「🌅 展示前厳選10」から、投稿時刻から30分以上先に
締切があるレースを的中確率が高い順に3つ選び、スレッド形式（1投稿目に1レース目、返信で2・3レース目）で投稿します
（`threads_morning.py`）。締切が過ぎた・間近のレースは飛ばして次のレースを繰り上げます。買い目はモデルのみ予想です。

- 1投稿目には「本日の厳選3レース」画像（日付・会場・R・締切・本命。`pick_card.render_morning_card`）を付ける。
  画像は Supabase Storage の公開バケット `threads-images` の `morning/<日付>_<時刻>.png` に置き、その公開URLをスレッズに渡す
  （書き込みは service_role だけ・一覧は取れない）。作れない・置けない・画像付きの投稿が失敗したときは画像なしで投稿し、
  理由を `threads_auto_posts.image_error` に残す（設定タブに出る）
- ON/OFF: 設定タブの「🧵 スレッズ連携」→「🌅 朝の無料3レース」（`app_settings.threads_auto_post_enabled`。初期値 OFF）
- 投稿しない日: 厳選が3レースそろわない日・厳選のデータに異常がある日（理由を記録する）
- 記録: `threads_auto_posts`（1日1行。成否・投稿したレース・買い目・本文・失敗の内容）。失敗は設定タブと予想タブに出る。
  同じ日に2回は投稿しない（1投稿もできなかった日だけ、手動実行の retry = true でやり直せる）
- note の記事と同じレースは、設定タブ・予想タブ・note 欄で警告する
- 文章は `threads_poster.build_morning_pick_text` の決まった型（展示前の予想・レース・締切・本命・買い目）。最後の投稿（3/3）には note の宣伝（`MORNING_NOTE_PROMO`）を入れる。
  後で Claude の文章にするときは `threads_morning.build_texts` に writer を渡す（失敗したらその投稿だけ決まった型）
- 止めるとき: アプリで OFF、または `select cron.unschedule('trigger-threads-morning');`

### note（全て有料・展示後）
予想タブの「📝 note記事（有料）」欄（`note_view.py`）。

- 全て有料（300円）として記録する（1日3本までの無料枠はやめた。今までの行はそのまま）
- 記事に載せる買い目を「モデルのみ予想」（初期値）か「両方の予想平均」から選ぶ。両方の予想平均は、
  そのレースで Claude の予想を取ったときだけ選べる。選んだ買い目は `note_publications.ticket_source`・`article_tickets` に保存
- 本文は Claude（Haiku。Secrets の `CLAUDE_ARTICLE_MODEL` で変えられる）が、選んだ買い目と展示後の予想展開を書く
  （`note_article.py`）。データに無いことは書かない・「絶対」「鉄板」などは使わない。破ったとき・失敗したときは今までの決まった型
- 買い目の欄は Claude に書かせず、選んだ買い目から作って本文の後ろに付ける
- 予想カード画像（会場・レース・締切、本線と抑え、1着確率のグラフ、スタート〜1マークの展開図）を作って保存できる
  （`pick_card.py`。買い目・1着確率は記事と同じ予想。日本語フォントは `packages.txt`）

### 夜の1日のまとめ
設定タブの「📊 本日のまとめ投稿」。「朝の無料3レース」と「noteのレース」を分けて載せる。朝のレースは投稿した買い目、
note のレースは記事に載せた買い目で的中を判定する。締めの一言（3パターン）は両方を合わせた的中率で決める。

## 的中確率の表示補正
新しいモデル（`ml`）では補正しない（補正なしで実際の的中率に合っているため）。以下は今までのモデルのときの補正。

予想画面の「この買い目の的中確率」は、各買い目の3連単確率の合計（補正前）をそのまま出すと
実際の的中率より低く出ます（事後予想 7,701レースで表示の平均26%に対し実際45%）。順番は
合っているので、事後予想の「補正前の値 → 候補内的中」から等張回帰（単調な変換）を作り、
表示する数字だけを実際の的中率に合わせています（`hit_calibration.py`）。買い目の選び方・資金配分は変えません。

- 作り直し: `hindcast.yml` の最後に動き、今の予想ロジックの版の補正が無いか、前回から7日たっていれば
  作り直します（週1回）。手動で作り直すときは `recalibrate: true` で起動します
- `hit_probability_calibrations` … 補正1回1行（変換表・帯ごとの当てはまり・時系列の検証・前回の補正の確認）
- 補正前と補正後の両方を保存: 固定予想と `prediction_results` は `hit_probability`（補正前）と
  `hit_probability_calibrated`（表示した補正後）・`hit_calibration_id`、事後予想は
  `candidate_hit_probability` と `candidate_hit_probability_calibrated`（その日より前のデータで作った補正）
- 検証画面の「表示した的中確率と実際の的中率」で、補正後・補正前それぞれを実際の的中率と比べられます

## PCで起動
```bash
pip install -r requirements.txt
streamlit run app.py
```

同じWi-Fi内のスマホから見る場合は、PCのローカルIPを使って
`http://PCのIP:8501` にアクセスします。OSのファイアウォール設定が必要な場合があります。

## スマホでいつでも使う
Streamlit Community Cloud等へこのフォルダをGitHub経由でデプロイすると、
Safari/ChromeからURLで利用できます。ホーム画面に追加すればアプリ風に使えます。

## 学習CSVの必須列
`venue,race_no,lane,racer_win_rate,local_win_rate,motor_2ren,boat_2ren,avg_st,finish`

1艇1行、finish=1が勝者です。

## 重要
- 公式ページのHTML構造が変更された場合、自動取得部分の修正が必要になることがあります。
- オリジナル展示・選手コメントは24場で公開形式が統一されていないため、v2では手入力併用です。
- コメント解析はルールベース。過去コメントを蓄積できれば、将来は学習型NLPに置き換え可能です。
- 3連単確率はv2では1着強度をもとにしたPlackett-Luce近似です。
- 利益を保証するものではありません。実運用前に日付順のバックテストを行ってください。
